## 原生与 Web 的产品边界

应用内显示我们自己的界面；只有学校 SSO 在内部官方登录窗完成。纯 Web/PWA 不能假定拥有 Android 设备桥。桌面/浏览器版应显示平台限制或尚未接入状态，不得静默切到 fixtures。学校登录与 Campus Helper 账号是两套会话。

受限桥只提供命名操作及校验后的 DTO，不提供任意 URL、脚本执行或导出 cookie 的接口。UI 只调用 service facade；HTML 解析、签名、CSRF、请求重试策略由 Codex 维护。学校请求失败不能通过改变视觉代码掩盖。

## 区间车：当前本地接口快照

以下是未推送原型的实际接口，不承诺云端已有对应文件。发布 CO-03 后以该 PR 的导出类型为准。Claude 可以先按此制作预览组件，但不复制原型 bridge 或自行注册另一个插件。

- `Schedule`：`id`、`date`（YYYY-MM-DD）、`departure` / `arrival`（HH:mm）、`from` / `to`（TC Campus 或 SIP Campus）、`pickup`；`route` 为 1（SIP → 太仓）或 2（太仓 → SIP）。ID 必须视为不透明标识，不硬编码班次。
- `Trip`：上述行程字段（无 route）及 `qrAvailable`。只展示当前学校可操作的本人行程；历史中无操作 ID 的 Booked 卡片不伪造 ID。若要新增只读历史视图，需独立设计历史 DTO 与能力标志。
- `shuttleAvailable()`：Android 桥可用性；`login()`：内部 SSO；`schedules(date, route)`：班次；`trips()`：本人可操作行程；`book(schedule)` / `cancel(trip)`：确认后的写入。
- 写入返回分别是 `{ confirmed: true, trip }` / `{ cancelled: true }`；必须通过 schema 并回读本人列表，才能显示成功。`RESULT_UNKNOWN` 必须先刷新本人行程，禁止自动再预约。
- `pass(trip)` 返回 `{ payload, validForMs }`；payload 只留设备内存，不能作为 fixture、日志或同步到服务器。使用返回寿命与单调时钟；不使用手机时间猜过期。
- `scan(trip)` 只报告学校验证状态；`changed` 不等于已成功上车。`onState` 和 `closePass` 管理前后台及离开页面；替换 UI 时必须保留这些行为。
- 错误至少区分未登录、请求中、结果未知、已预约、订单已不可操作、乘车码未开放、需要更新 WebView、网络/学校响应异常。

UI 状态应覆盖：未连接、连接中、加载、空结果、学校拒绝、离线、会话失效、预约待确认、写入中、结果未知、取消待确认、QR 未开放/加载/有效/过期/后台/恢复/状态改变。QR 有效期间截图保护不应因视觉重构被删除。

## 学校协议事实与限制

区间车为同源 HTML/表单服务，不是已发现的 JSON 开放 API。查询为 `/schedule/list`；创建使用实时班次表单与 CSRF。班次 ID、预约结果 ID、行程 ID 不是同一个 ID。取消确认页 GET 本身不取消；实际取消也是会改变状态的 GET。UI 不得预取这些写入地址。

非运营日期可能返回其他日期的班次；必须核对返回表单日期。当前查询拒绝错配数据，后续可增加学校可选日期契约以改善 UI。班次、提前预约窗口、取消资格和政策均以学校实时数据为准。

讨论室：官网已验证太仓 1F，资源 campusId=2；菜单路由参数不能按名字猜测 campusId。房间数量/规则为当时快照，不能变成永久常量。学生配置快照为 2–5 人、30–180 分钟、08:00–22:00、0–3 天；迟到 30 分钟取消不等于“提前 30 分钟取消”。本人计入组员，不得复制本人凑数。创建候选为 POST `/ic-web/reserve`，取消候选为 POST `/ic-web/reserve/delete`；尚无成功写入验证，不给 UI 编造返回值。网关403/登录页不能显示为无房间。

AMS：候选 GET `/xjtlu/sign/qRCodeSign`（code 课堂码、type=2）会改变考勤记录，不能当只读查询或预取。沿用学校当前页面请求上下文；不导出 AMS 自有 token。静态成功分支不算成功签到证明。
